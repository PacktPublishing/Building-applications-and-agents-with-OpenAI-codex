Installed-source checks established:

- `CodeInterpreterTool.tool_config` accepts the code interpreter tool with an
  explicit container ID.
- `containers.create` accepts `file_ids`, `memory_limit="1g"`, and
  `expires_after={"anchor":"last_active_at","minutes":20}`.
- `containers.delete` returns None; `files.delete` returns a deletion object.
- `ResponseCodeInterpreterToolCall` exposes status, container ID, code, and outputs.
- `ModelSettings.response_include` accepts `code_interpreter_call.outputs`.
- `ResponseOutputMessage` annotations include `AnnotationContainerFileCitation`.
- `containers.files.content.retrieve` returns binary content; this is distinct
  from retrieving content for an original Files API upload.

The reference uses an explicit container for resource tracking, although the
upstream example demonstrates auto mode. All chart creation stays in the
hosted SDK agent flow. Local code only prepares/validates data, handles files,
and checks results in tests. Model selection uses the existing SDK default or
an explicit environment override; no model upgrade was made.
